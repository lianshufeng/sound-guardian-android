# 触摸互动与陪伴倾听

## 当前实现

语音继续使用已集成的 sherpa-onnx 1.13.8：KWS 唤醒、Kokoro 中文女声播报、Silero VAD 分段、SenseVoice INT8 同时识别中文文字及声音情绪。环境声音守护继续使用共享 YAMNet。这些本地能力无需网络，不新增麦克风或播放器。另行启用“AI模型”后，明确唤醒/点击左上角“安澜”和关怀回复可进入网络对话，顶部不再单列“说话”按钮；统一输入准备与提示音由 InputSessionController 管理，底部波浪由页面展示，详见 [AI 对话计划与实施](ai-dialogue-development-plan.md)。播放期间仍抑制识别，首版不支持语音打断。

首次准备资源：

```powershell
powershell -ExecutionPolicy Bypass -File tools/prepare-tts.ps1
powershell -ExecutionPolicy Bypass -File tools/prepare-understanding.ps1
```

SenseVoice 权重为 239,233,841 字节；Silero VAD 为 643,854 字节。输入均为共享的 16 kHz 单声道音频，文件来源及固定 SHA-256 在 `core/src/main/assets/understanding/manifest.json`。模型、运行库和许可证分别维护，不能用运行库许可证代替模型许可证。

## 触摸

轻点脸部先短暂惊讶、再微笑；停留约 800 毫秒变害羞，带淡腮红；持续往返抚摸变蹭手，眯眼并向手指靠近。视线跟随触摸坐标；松手后约 600 毫秒收回视线，回应保留约 1.4 秒。困倦或打盹时先醒来。小幅抖动不会被当成抚摸，多指触摸或手势取消立即清除状态；离开页面也清除按压状态。

`TouchInteraction` 是不依赖 Android 的手势解释器，`FaceView` 使用现有 Canvas 几何绘制，不加载新动画框架或 AI 模型。时间配置在安澜 `behavior.json`。

## 倾听

默认关闭持续陪伴倾听。喊“小安”后，仍同步播报及显示“我在”。配置并启用“AI模型”时，首轮经同一输入控制器准备模型，跳过额外叮声并仅保留150毫秒尾音保护，输入就绪即显示“请说话”；后续轮次和关怀ASK仍按提示音开关及650毫秒尾音保护进入输入。底部白蓝渐变波浪以低幅呼吸提示状态，不显示倒计时文字；每轮就绪后3秒未开口仍在后台安静退出，已开口等待 VAD 话轮及识别完成，最长30秒讲话加8秒识别宽限。实际倾听且 VAD 检测到讲话时叠加短时音量起伏；准备、提示音、识别及播报阶段仅低幅流动。准备及提示音阶段保持注意表情，就绪才显示聆听表情；触摸和高优先级声音仍按原有优先级调度。移除底部结束按钮，返回键结束当前对话或关怀，菜单内仍先返回菜单。未启用或未配置AI时，保持原有本地窗口：播报结束并等待500毫秒尾音后开启，无讲话约4秒结束，有讲话时延长，本地窗口也显示波浪与“请说话”。设置中开启“持续陪伴倾听”后，本地陪伴识别继续受该开关控制；AI会话超时不会关闭它，也不自动上传全部文字。电视对白可能被识别为讲话。

波浪只消费 `InteractionPorts.UnderstandingState` 的归一化短时音量和临时窗口状态。音量由现有 VAD 工作线程从共享 PCM 计算，通过主线程合并状态发布；300毫秒前的音量不再作为实时证据，取消、抑制及会话替换清零，窗口结束后隐藏。仅保留最新标量，默认不保存录音或音量历史。波浪约30帧/秒，退出页面或隐藏时停止刷新；真机跟随感和性能需单独验收。

2026-10-17 根据唤醒命中偏低的反馈，将共享 `wakeword/keywords.txt` 中“小安”的检测阈值从 0.10 小幅降低为 0.08，关键词加分仍为 1.5；重复唤醒冷却随后按用户要求从 6 秒缩短为 3 秒，由 `InteractionPorts.WAKE_COOLDOWN_MS` 统一检测与表情层，播报准备、播放和尾音抑制保留。vivo V2505A / Android 16 / ARM64 真机上，正常、快读和更快合成“小安”均检出，正常及快读的普通说话、相近称呼均未检出；原有正负样本与重置、重建回归通过。快读由 Microsoft Huihui Desktop 的 Rate 2 / 4 生成，仅为合成语料验证，不代表真人命中率已提高多少；仍需自然语速、远近距离及电视背景声实测。生成脚本 `tools/create-wakeword-fixtures.ps1 -OnlySpeedVariants` 只补充快读样本，不修改原有对照语料。

2026-10-18用户反馈自然快语速、非标准发音仍难唤醒，界面有Speech事件也不能证明KWS命中。本轮将关键词加分单项从1.5调至1.8，触发阈值0.08、3秒冷却和播报抑制保持原值；Debug只增加就绪/命中/抑制和冷却元数据日志，不保存录音。当前仍只有“小安”的标准词元路径，不能据此宣称已适配各类口音；本轮回归及真人待验收项见[自然发音调优](wakeword-robustness.md)。

共享 PCM 经轻量 VAD 检测讲话，随后在独立工作线程运行 SenseVoice。VAD 最短有效讲话 0.35 秒，停顿 0.65 秒结束短句，长句按约 4 秒片段切分。讲话时先给予聆听表情，识别完成后再回应情绪；第一版为分段文字，不是逐字流式字幕。

同次推理返回文字、情绪标签、语言、声音事件和耗时。`UnderstandingWorker` 实现 `InteractionPorts.SpeechInput`，按顺序回调有效文字和完整识别信息；设备状态页可查看最近结果。默认不持久化录音或转写，不接开放对话。用户可单独开启首批关怀，ASK 使用所属倾听窗口返回文字与情绪；可选保存仅覆盖关怀回复，见 [关怀实施记录](care-implementation.md)。

| 声音情绪 | 回应 |
|---|---|
| HAPPY | 首段微笑，连续两段一致后开心 |
| SAD、FEARFUL、ANGRY、DISGUSTED | 温和关切 |
| SURPRISED | 专注留意 |
| NEUTRAL、未知 | 自然聆听 |

情绪至少保持约 2 秒，最近反馈保留约 3.5 秒；随后按当前讲话和守护状态恢复。声音情绪是声学线索，不能当作真实心理状态；不以音量直接推断兴奋，不编造模型未提供的概率。

## 调度与性能

`BehaviorEngine` 统一调度：高优先级守护事件优先于唤醒/播报，直接触摸可覆盖被动共情，已确认普通事件按原等级处理，待机最后。覆盖表情不会暂停声音守护或事件记录。

VAD 与识别分线程；PCM 队列最多 16 块，待识别片段最多 2 段。纯陪伴模式可跳过过期片段；显式文字会话超载或超时会报告中断，不能静默丢字。采集断流、取消、模式切换、TTS 抑制及服务关闭会使旧会话失效，旧结果不得改变新会话。识别线程默认 1 个，模型初始化、推理和释放在全局串行队列执行，避免服务快速重启时重复驻留。

SenseVoice可在唤醒回应及普通整句对话播报期间提前准备，准备请求只保留最新输入所有者，不提前接收PCM；流式回答暂不提前加载ASR，以免抢占后续段合成资源。普通设备空闲约60秒后释放，约4GB或系统标记低内存的设备为10秒。Kokoro FP32启动预热“我在”、空闲时补齐响指回应后释放；PCM16缓存最多4条，节省档512KiB、普通档2MiB。动态播报按需加载，普通档可在网络等待时准备TTS。TTS和SenseVoice共用单项重型作业许可，加载还检查系统可用内存；初始估计TTS512MiB、SenseVoice320MiB尚待真机校准。内存紧张时暂停倾听、使旧结果失效、释放模型，TTS缓存只保留“我在”，守护和唤醒继续。播报准备、播放及尾音仍暂停VAD/文字/情绪输入，业务播报仍走唯一`SpeechPlayback`。

2026-10-18移除唤醒播报前600毫秒等待；Conversation/Care不再额外叠加各自尾音，统一输入控制器保留`dialogue.json`的650毫秒最终等待。未启用AI的本地窗口仍保留500毫秒尾音。没有缩短声学安全等待；实际尾音、自声误识别、目标手机时延和长期资源仍待真机验收，见[本轮记录](interaction-performance-acceptance.md)。

## 验证记录与待验收项

2026-10-17 在 Android 17 / API 37、x86_64 模拟器使用固定官方中文样本验证：同次推理返回“开饭时间早上9点至下午5点。”、`NEUTRAL`、`Speech`、`zh`。样本时长 5.592 秒；最终回归加载约 1.48 秒，首次识别约 629 毫秒，预热后约 620 毫秒。测试样本及哈希见 `core/src/androidTest/assets/understanding-test/manifest.json`。

YAMNet、KWS、Kokoro 与 SenseVoice 四模型共存，并行执行声音检测及文字识别的测试通过；早期未量化 TTS 共存采样的 PSS 约 897,310 KiB（约 876 MiB），仅作为历史基线。改用 Kokoro int8 后，Android 17 / API 37、x86_64 模拟器的单项采样为：TTS 加载 PSS 约 316 MiB、长句合成 PSS 约 386 MiB，释放后约 96 MiB；SenseVoice 加载约 361 MiB，6 段样本识别约 350 MiB，释放后约 107 MiB；YAMNet/KWS/VAD/SenseVoice 共存约 393 MiB。TTS 长句合成约 8.1 秒、SenseVoice 6 段共约 3.7 秒；这些是模拟器 CPU 数据，不是目标真机时延。完整守护在手动模拟器采样中约 155 MiB PSS，后台等待约 12% 单核口径；仪器测试受测试线程和并发负载影响，不能作为 CPU 峰值结论。

当前资源预算使安澜在 4 GB 级设备上不必长期驻留 TTS 和倾听模型；首次播报或首次识别会重新加载，低端机可能增加等待时间。Debug APK 仍包含四种 ABI，发布时应使用 AAB/ABI 拆分；当前安澜 Debug APK 的资产约为 TTS 386 MiB、SenseVoice 229 MiB、KWS 12.5 MiB，安装存储量不能代表运行内存。

2026-10-17 在 vivo V2505A / Android 16 / ARM64 真机定位无声：正式播报的 PCM 全零，INT8 合成结果 22,800 个样本全部为 NaN；2 线程和 1 线程均失败。有效样本经同一手机可正常播放，媒体音量和权限不是本次根因。改用官方 FP32 权重，音色及统一播报入口保持一致，并拒绝 NaN/Infinity 或静音结果。FP32 样本峰值约 0.412、RMS 约 0.079，未含非有限值；用户已确认正式统一接口的“我在”可听，字幕起止测试通过。上文 INT8 模拟器资源数据仅为历史记录，不能代表修复后的资源消耗；4 GB 目标真机仍须重新验收。

同日该真机前台守护下连续合成“我在→长句→我在”通过：加载额外 TTS 前 PSS 314,181 KiB / native 已分配 92,860 KiB，加载后 737,149 / 555,233 KiB，三次合成后 690,891 / 684,887 KiB，关闭模型 1 秒后 307,483 / 120,958 KiB。以上是阶段快照，不是完整峰值或长期无泄漏证明。单独后台 `ResourceProfileDeviceTest` 被 vivo 冻结（系统进程记录 `isFrozen=true`），已终止，不将超时归因于引擎死锁，也不采用该轮释放数据；前台复验保留原引擎复用及空闲释放策略。

本次修复验证：core 3 项、安澜 32 项单元测试，安澜 6 项播报定向真机测试及原 App 1 项共享模型推理测试通过；两款 Debug 构建、安澜 lint 通过。两款 APK 的 392 / 6 项共享资产分别与源文件 SHA-256 一致，原 App 未包含三个未启用语音目录，安澜未残留 INT8 TTS 权重；重新生成的安澜 Debug APK 为 795,060,137 字节（约 758 MiB）。

首次集成时，28 项单元测试、安澜 20 项设备测试及原 App 1 项共享核心设备测试通过，两款 Debug APK 构建及安澜 lint 通过。随后按启用能力打包：原 App 保留 6 项共享声音资产，安澜保留完整 392 项，均校验与 core 源文件一致。已验证手势和优先级、连续结果去重、取消、表情恢复、VAD 静音/讲话分段、TTS 自声抑制、过载报告、内存回收后新会话及真实中文文字与情绪元数据闭环。中性单样本不能证明各种情绪的识别准确率。后续结构及并发优化见 [代码审查记录](architecture-review.md)。

目标设备尚未连接：真机冷/热启动耗时、峰值内存、CPU、帧率、温度、耗电及一小时连续运行仍待验收；不同说话人、距离、方言、开心/悲伤/生气、噪声及电视对白需补充样本，记录文字错误率和情绪混淆情况。性能目标为触摸反馈低于 100 毫秒、3 秒语音片段识别争取低于 1 秒，不能把模拟器结果直接当作通过真机验收。
