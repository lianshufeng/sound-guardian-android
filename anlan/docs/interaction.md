# 触摸互动与陪伴倾听

模型声音文字保留分数不低于0.25的所有有限值分类，按分数排序，不再截为前三类，列表仍由共享模型的521类契约限定。每500毫秒最多新增一个气泡，同类显示间隔4.8秒，可见气泡最多6个；气泡2.4秒向上移动并淡出。限频或可见数量已满时，按首次候选顺序最多暂存12类，同类只更新分数与最后出现时间；页面定期刷新会继续排空候选，不要求出现新推理快照，超过3.2秒未再出现的候选丢弃。隐藏、移出窗口或停止守护时同时清除候选和气泡，防止恢复后补播旧文字。仅改善展示覆盖，不改变共享事件规则、表情优先级或唤醒参数；混合声音可能导致分类低分或唤醒漏检，不能宣称已识别全部声音。回归入口为`ModelResultsDeviceTest`，声学诊断不能当作真人远场验收。

AI对话按轮流方式运行：当前话轮识别完成后立即关闭输入，进入“想一想”、模型生成和语音准备；本轮生成及整段播放期间普通讲话不会打断，明确再次说“小糖”会取消当前回答并重新唤醒。新唤醒后的输入窗口锁定本轮，重复“小糖”也不能打断，必须完成本轮输入；播放完成后才自动开放下一轮输入。无正文等待3秒显示“还在想，请稍候”，有正文显示“正在准备声音”。高优先级事件或返回键仍可结束当前会话；电视对白在实际输入窗口内仍可能误触发。配置与契约见[AI对话](ai-dialogue-development-plan.md#轮流对话当前行为)。

“显示声音强度”在左上角展示0～100的相对录音强度。复用唯一采集流最新约100毫秒PCM，在页面线程计算RMS并将−60～0 dBFS映射为0～100（范围外截断），可见页面约100毫秒刷新，不等待YAMNet推理；超过500毫秒无新数据、服务停止或会话重建时归零。只保留一块临时PCM，不保存录音；该数值不是校准的环境分贝，不能跨设备比较，也不改变事件判定或倾听开关。

## 当前实现

“设置 → 性能模式”默认“高性能”：TTS启动预热后保留，SenseVoice在持续倾听或交互准备时加载后保留，不因空闲释放；“节省内存”保持原有按需加载、低内存档10秒/普通档60秒空闲释放，TTS启动短句预热结束即释放。模式保存在`interaction`偏好的`performance_mode`（`high`/`low_power`），切换即时生效；切到节省内存后由所属串行线程按最后使用时间释放，不打断进行中的合成/识别。持续倾听开关、输入抑制、加载内存准入及重型作业串行限制保持独立，两种模式都响应内存回收和服务停止；恢复使用时重新加载。高性能使用更多常驻内存，节省内存表示空闲时释放模型，尚无真机耗电对照结论；内部保存值`low_power`保留以兼容已有配置。两种模式验收入口为`PerformanceModeDeviceTest`，参数`performance_mode=high`或`low_power`，记录仅放`evaluation/`。

启动预热任务结束后才报告播报“已就绪”；预热被业务请求抢占时释放该初始化实例，由后续动态请求重新加载，高性能仍保留后续成功加载的实例。内存回收会使旧预热代次失效，旧任务不得回填缓存或更新就绪状态。

语音继续使用已集成的 sherpa-onnx 1.13.8：KWS 唤醒、VITS 中文播报、Silero VAD 分段、SenseVoice INT8 同时识别中文文字及声音情绪。环境声音守护继续使用共享 YAMNet。这些本地能力无需网络，不新增麦克风或播放器。另行启用“AI模型”后，明确唤醒/点击左上角“红糖”和关怀回复可进入网络对话，顶部不再单列“说话”按钮；统一输入准备与提示音由 InputSessionController 管理，底部波浪由页面展示，详见 [AI 对话计划与实施](ai-dialogue-development-plan.md)。模型生成、语音准备和播放期间暂停普通语音识别，但KWS仍接受明确“小糖”以抢占回答；输入窗口内不支持重复唤醒打断。

首次准备资源：

```powershell
powershell -ExecutionPolicy Bypass -File tools/prepare-tts.ps1
powershell -ExecutionPolicy Bypass -File tools/prepare-understanding.ps1
```

SenseVoice 权重为 239,233,841 字节；Silero VAD 为 643,854 字节。输入均为共享的 16 kHz 单声道音频，文件来源及固定 SHA-256 在 `core/src/main/assets/understanding/manifest.json`。模型、运行库和许可证分别维护，不能用运行库许可证代替模型许可证。

## 触摸

轻点脸部先短暂惊讶、再微笑；停留约 800 毫秒变害羞，带淡腮红；持续往返抚摸变蹭手，眯眼并向手指靠近。视线跟随触摸坐标；松手后约 600 毫秒收回视线，回应保留约 1.4 秒。困倦或打盹时先醒来。小幅抖动不会被当成抚摸，多指触摸或手势取消立即清除状态；离开页面也清除按压状态。

`TouchInteraction` 是不依赖 Android 的手势解释器，`FaceView` 使用现有 Canvas 几何绘制，不加载新动画框架或 AI 模型。时间配置在红糖 `behavior.json`。

## 倾听

默认关闭持续陪伴。喊“小糖”后，仍同步播报及显示“我在”。配置并启用“AI模型”时，首轮经同一输入控制器准备模型，跳过额外叮声并仅保留150毫秒尾音保护，输入就绪即显示“请说话”；后续轮次和关怀ASK仍按提示音开关及650毫秒尾音保护进入输入。底部白蓝渐变波浪以低幅呼吸提示状态，不显示倒计时文字；首轮就绪后6秒、后续轮次3秒未开口在后台安静退出，已开口等待 VAD 话轮及识别完成，最长30秒讲话加8秒识别宽限。实际倾听且 VAD 检测到讲话时叠加短时音量起伏；准备、提示音、识别及播报阶段仅低幅流动。准备及提示音阶段保持注意表情，就绪才显示聆听表情；触摸和高优先级声音仍按原有优先级调度。移除底部结束按钮，返回键结束当前对话或关怀，菜单内仍先返回菜单。未启用或未配置AI时，保持原有本地窗口：播报结束并等待500毫秒尾音后开启，无讲话约4秒结束，有讲话时延长，本地窗口也显示波浪与“请说话”。设置中开启“持续陪伴”后，本地陪伴识别继续受该开关控制；AI会话超时不会关闭它，也不自动上传全部文字。电视对白可能被识别为讲话。

波浪只消费 `InteractionPorts.UnderstandingState` 的归一化短时音量和临时窗口状态。音量由现有 VAD 工作线程从共享 PCM 计算，通过主线程合并状态发布；300毫秒前的音量不再作为实时证据，取消、抑制及会话替换清零，窗口结束后隐藏。仅保留最新标量，默认不保存录音或音量历史。波浪约30帧/秒，退出页面或隐藏时停止刷新；真机跟随感和性能需单独验收。

2026-10-17 根据唤醒命中偏低的反馈，将共享 `wakeword/keywords.txt` 中“小糖”的检测阈值从 0.10 小幅降低为 0.08，关键词加分仍为 1.5；重复唤醒冷却随后按用户要求从 6 秒缩短为 3 秒，由 `InteractionPorts.WAKE_COOLDOWN_MS` 统一检测与表情层，播报准备、播放和尾音抑制保留。vivo V2505A / Android 16 / ARM64 真机上，正常、快读和更快合成“小糖”均检出，正常及快读的普通说话、相近称呼均未检出；原有正负样本与重置、重建回归通过。快读由 Microsoft Huihui Desktop 的 Rate 2 / 4 生成，仅为合成语料验证，不代表真人命中率已提高多少；仍需自然语速、远近距离及电视背景声实测。生成脚本 `tools/create-wakeword-fixtures.ps1 -OnlySpeedVariants` 只补充快读样本，不修改原有对照语料。

2026-10-18用户反馈自然快语速、非标准发音仍难唤醒，界面有Speech事件也不能证明KWS命中。本轮将关键词加分单项从1.5调至1.8，触发阈值0.08、3秒冷却和播报抑制保持原值；Debug只增加就绪/命中/抑制和冷却元数据日志，不保存录音。当前仍只有“小糖”的标准词元路径，不能据此宣称已适配各类口音；本轮回归及真人待验收项见[自然发音调优](../../evaluation/wakeword-robustness.md)。

共享 PCM 经轻量 VAD 检测讲话，随后在独立工作线程运行 SenseVoice。VAD 最短有效讲话 0.35 秒，停顿 2.5 秒结束短句，长句按约 4 秒片段切分。讲话时先给予聆听表情，识别完成后再回应情绪；第一版为分段文字，不是逐字流式字幕。

同次推理返回文字、情绪标签、语言、声音事件和耗时。`UnderstandingWorker` 实现 `InteractionPorts.SpeechInput`，按顺序回调有效文字和完整识别信息；设备状态页可查看最近结果。默认不持久化录音或转写，不接开放对话。用户可单独开启首批关怀，ASK 使用所属倾听窗口返回文字与情绪；可选保存仅覆盖关怀回复，见 [关怀实施记录](care-implementation.md)。

| 声音情绪 | 回应 |
|---|---|
| HAPPY | 首段微笑，连续两段一致后开心 |
| SAD、FEARFUL、ANGRY、DISGUSTED | 温和关切 |
| SURPRISED | 专注留意 |
| NEUTRAL、未知 | 自然聆听 |

情绪至少保持约 2 秒，最近反馈保留约 3.5 秒；随后按当前讲话和守护状态恢复。声音情绪是声学线索，不能当作真实心理状态；不以音量直接推断兴奋，不编造模型未提供的概率。

## 调度与性能

`BehaviorEngine` 统一调度：高优先级守护事件优先于唤醒/播报，直接触摸可覆盖被动共情，已确认普通事件按原等级处理，待机最后。覆盖表情不会暂停声音守护或事件记录。

VAD 与识别分线程；PCM 队列最多 16 块，待识别片段最多 2 段。纯陪伴模式可跳过过期片段；显式文字会话超载或超时会报告中断，不能静默丢字。采集断流、取消、模式切换、TTS 抑制及服务关闭会使旧会话失效，旧结果不得改变新会话。识别工作器默认 1 个，SenseVoice 模型内部使用 2 个 CPU 推理线程；模型初始化、推理和释放仍在全局串行队列执行，避免服务快速重启时重复驻留。线程数需结合目标真机的识别时延、内存和发热重新验收。

SenseVoice可在唤醒回应及普通整句对话播报期间提前准备，准备请求只保留最新输入所有者，不提前接收PCM；流式回答在本轮输入关闭后提交，避免抢占当前回答。节省内存下普通设备空闲约60秒后释放，约4GB或系统标记低内存的设备为10秒；高性能保留已加载模型。VITS启动预热“我在”、空闲时补齐响指回应，节省内存随后释放；PCM16缓存最多4条，节省档512KiB、普通档2MiB。动态播报按需加载，普通档可在网络等待时准备TTS。TTS和SenseVoice共用单项重型作业许可，加载还检查系统可用内存；初始估计TTS512MiB、SenseVoice320MiB尚待真机校准。内存紧张时暂停倾听、使旧结果失效、释放模型，TTS缓存只保留“我在”，守护和唤醒继续。普通播报准备、播放及尾音均暂停VAD/文字/情绪输入；AI回答完成整段播放后才恢复下一轮输入，业务播报仍走唯一`SpeechPlayback`。

2026-10-18移除唤醒播报前600毫秒等待；Conversation/Care不再额外叠加各自尾音，统一输入控制器保留`dialogue.json`的650毫秒最终等待。未启用AI的本地窗口仍保留500毫秒尾音。没有缩短声学安全等待；实际尾音、自声误识别、目标手机时延和长期资源仍待真机验收，见[本轮记录](../../evaluation/interaction-performance-acceptance.md)。

## 验证记录与待验收项

2026-10-17 在 Android 17 / API 37、x86_64 模拟器使用固定官方中文样本验证：同次推理返回“开饭时间早上9点至下午5点。”、`NEUTRAL`、`Speech`、`zh`。样本时长 5.592 秒；最终回归加载约 1.48 秒，首次识别约 629 毫秒，预热后约 620 毫秒。测试样本及哈希见 `core/src/androidTest/assets/understanding-test/manifest.json`。

VITS 替换后的 x86_64 仿真器实测：116 字热合成约 8.0 秒（2线程）、5.6 秒（3线程）、4.5 秒（4线程），生成音频约19.5秒，PSS约400MiB；1线程约15.3秒。该结果不代表 ARM64 真机，音质、温度、耗电和长期资源仍待验收。

当前资源预算使红糖在 4 GB 级设备上不必长期驻留 TTS 和倾听模型；首次播报或首次识别会重新加载，低端机可能增加等待时间。Debug APK 仍包含四种 ABI，发布时应使用 AAB/ABI 拆分；当前红糖 Debug APK 的资产约为 TTS 386 MiB、SenseVoice 229 MiB、KWS 12.5 MiB，安装存储量不能代表运行内存。

历史 Kokoro 版本在 2026-10-17 的 vivo V2505A / Android 16 / ARM64 真机定位无声：正式播报的 PCM 全零，INT8 合成结果 22,800 个样本全部为 NaN；2 线程和 1 线程均失败。有效样本经同一手机可正常播放，媒体音量和权限不是本次根因。改用官方 FP32 权重，音色及统一播报入口保持一致，并拒绝 NaN/Infinity 或静音结果。FP32 样本峰值约 0.412、RMS 约 0.079，未含非有限值；用户已确认正式统一接口的“我在”可听，字幕起止测试通过。上文 INT8 模拟器资源数据仅为历史记录，不能代表修复后的资源消耗；4 GB 目标真机仍须重新验收。

同日该真机前台守护下连续合成“我在→长句→我在”通过：加载额外 TTS 前 PSS 314,181 KiB / native 已分配 92,860 KiB，加载后 737,149 / 555,233 KiB，三次合成后 690,891 / 684,887 KiB，关闭模型 1 秒后 307,483 / 120,958 KiB。以上是阶段快照，不是完整峰值或长期无泄漏证明。单独后台 `ResourceProfileDeviceTest` 被 vivo 冻结（系统进程记录 `isFrozen=true`），已终止，不将超时归因于引擎死锁，也不采用该轮释放数据；前台复验保留原引擎复用及空闲释放策略。
