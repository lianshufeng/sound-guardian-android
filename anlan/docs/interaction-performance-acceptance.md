# 交互性能实施与验收

日期：2026-10-18。主要调度优化已实施；目标手机未连接，真机性能及长期稳定性尚未验收。本文只将本轮实际执行的检查列为证据，历史结果不算本次通过。

## 实现范围

- 唯一AudioRecord只分发PCM；声音推理和事件确认迁至GuardAudioPipeline，8块队列溢出保留最新块，采样序号断开即清除窗口及连续证据。共享规则、响指计数及阈值不变。
- EventHistoryWriter独立写库，300个待更新ID合并及300个版本记录有界；同时间戳终态优先，更新结束时间仍允许共享规则合并活动事件。写入失败或溢出记录失败元数据，不宣称记录成功；未新增存储故障界面。
- 去掉唤醒播报前600毫秒等待；缓存回应可与识别准备重叠。Conversation/Care不再自行叠加尾音，仍经同一个InputSessionController播放提示音并保留650毫秒最终等待。未开启AI的本地窗口保留500毫秒尾音。
- 模型准备不绑定PCM epoch；输入控制器租约决定有效所有者，准备请求合并为最新所有者，内存回收使旧预热失效，旧空闲释放重新检查使用时间。3秒无声时限仍从实际就绪开始，Care ASK保留自己的回复时限。
- 普通播报合成后交给同一播放消费线程；“我在”、响指固定回应缓存为PCM16，最多4条、节省档512KiB/普通档2MiB，键含配置、模型版本及文字。提示音和缓存绕过繁忙native工作器；只有一个实际播放器及活动会话。响指缓存补齐被打断或回收后，首次仍会合成。
- 内存回收明确取消普通及流式播报，只保留既有“我在”缓存；缓存写入与回收按同一资源代次和短锁校验，旧合成不能在回收后重新填入响指缓存。
- TTS/SenseVoice加载、计算共用一个可取消重型作业许可，YAMNet/KWS/VAD不等待该许可。普通档网络等待时准备TTS，普通整句对话播放时准备ASR；流式播放不抢占后续段的资源。模型空闲释放仍为10/60秒。
- 加载检查系统可用内存及lowMemory，初始估计TTS512MiB、SenseVoice320MiB并保留系统阈值/128MiB裕量。这不是按目标手机PSS、加载峰值校准的完整预算，也不能保证不会OOM。
- InteractionTrace最多512条数字元数据，包含阶段、ID、单调时长及数量，不保存正文、凭据或录音。未来远程仍只沿用Care统一提交、去重、有效期和取消契约，没有实现网络入口。

## 测量口径与目标缺口

缓存/提示音从已准入请求到AudioTrack实际调用play及同步开始回调计时，包含主线程与播放队列；不是物理扬声器第一声。50次请求交替响指缓存/提示音，并阻塞native工作器后立即取消，不能冒充自然完整播报或长稳。

动态测试使用固定中文短句，20次先回收合成器再请求、50次保留合成器；每次实际播放开始后取消。冷样本指模型重新加载，未清系统文件缓存或重启进程。RTF=持有重型许可后的native合成耗时/原始生成音频时长，排除资源排队；首声包含排队、加载、PCM准备和播放启动。单句样本不代表所有长度或ARM64表现。

缓存/动态基准停止真实守护服务，使用单个播报后端，不代表守护并行负载。PCM集成复用正式会话、识别和播报组件，由测试适配器绑定输入/播报；GuardianService完整链路另由唤醒、字幕、关怀播放等设备用例覆盖，仍没有物理麦克风端到端证据。

动态指标来自60项完整回归，缓存/提示音及取消调用指标来自交付APK的19项定向复验。缓存回收补丁不改变动态分句、模型或语速；各次测量失败数均为0。

### 优化前后对比限制

本轮实施前未建立同条件冷热基线，不能计算可信的整体提速比例、动态合成提升或内存下降幅度。唤醒固定流程从约1900毫秒降至约800毫秒，仅是移除600毫秒动画等待和500毫秒串行尾音后的代码推导，不含“我在”播放、模型准备及资源排队，不能当作唤醒端到端实测。

历史同名流式用例在`evaluation/ai-android17-speech-regression.log`记录4184毫秒，本轮为7321毫秒。两次未统一模型驻留、启动预热及系统负载，只能视为可能回退的信号，不能宣称动态聊天首段已提速；仍需优化前后版本同条件A/B复验。

尚未完成：目标手机冷20/热50次唤醒和麦克风话轮、自声/提示音回灌、真人响指与混淆声音、真实网络对话复验、视觉及停止声学P95、低内存档加载峰值/温度耗电、30分钟及2小时混合长稳。没有缩短尾音或修改流式分句参数；native PCM增量播放仍为条件实验，尚未实现。
