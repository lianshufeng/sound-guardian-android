## 验收方法与边界

- 规则矩阵使用隔离偏好和 SQLite，向真实 LocalCarePolicy、CareCoordinator 输入已确认事件、有效/失效天气、文字及情绪；播报和输入边界使用可控实现，验证触发、去重、限频及终态。此层不证明 YAMNet 的真实环境准确率。
- 独立真实服务测试执行同一 SpeechPlayback 的 TTS，检查播放完成后才开启 ASK、无回复超时及安静时段拒绝。真实模型测试使用固定 PCM 验证中文文字、原始情绪标签及话轮结束，检查多引擎共存、播报抑制和回收重载。
- “无输入”用例临时静音模拟器麦克风并恢复原状态；固定 PCM 识别不依赖现场噪声，不新增麦克风采集。
- 情绪矩阵注入标签只验证编排。真实中性样本通过不代表 SAD/ANGRY/FEARFUL 等情绪分类准确率通过；没有概率就不生成概率。
- 一小时测试每五分钟执行 NOTICE→ASK→屏幕反馈、真实固定 PCM 识别、低内存通知、前后台切换；每分钟采样 PSS/native/CPU，每秒检查守护状态。屏幕回复明确标记 SCREEN，真实 ASR 回复另由专项用例验证。
- 一小时首轮于 370.559 秒失败：测试框架 `startActivitySync` 回前台等待空闲超时。已改为系统 `am start` 后重跑，保留失败日志 `evaluation/care-soak-acceptance.log`，不将首轮计为通过。

### 样本及资源统计口径

中文 ASR 固定样本来自 sherpa-onnx SenseVoice 模型仓库的 `test_wavs/zh.wav`，转换为 16 kHz PCM；来源和哈希在 `core/src/androidTest/assets/understanding-test/manifest.json`。唤醒部分样本由 `tools/create-wakeword-fixtures.ps1` 使用 Microsoft 中文合成语音生成。场景矩阵由测试人工构造已确认事件/情绪/天气，不是本轮物理麦克风实录。

一小时服务运行真实共享音频采集链路，但平台麦克风静音；固定 PCM 通过 UnderstandingWorker 接口送入真实 VAD 与 SenseVoice，播报走真实 SpeechPlayback/TTS；ASK 在此持续测试用屏幕反馈结束。资源读自模拟器目标进程，不是模拟值，也不是单个关怀方法的净开销。

重跑的 60 个分钟样本全部为 LISTENING。采样峰值 PSS 781,987 KiB（约 763.7 MiB）、native 已分配 696,456 KiB（约 680.1 MiB）；首样本后 PSS 范围 164,754—185,664 KiB，末样本 PSS 181,833 / native 71,441 KiB。分钟采样可能错过瞬时峰值，不能称为完整峰值或无泄漏证明。

截至最后样本，3,574,216 ms 墙钟时间消耗 1,629,808 ms 进程 CPU，平均约 45.6% 单核口径。包含前台动画、后台守护、周期播报/识别及仪器测试开销，不能作为纯后台守护或单模型 CPU。统计见 `evaluation/care-soak-resource-summary.json`。结束前最终 NOTICE 与固定 PCM 识别均通过。

## 本轮发现并修复

1. 晚安流程先设置暂停导致自己的关怀被拒绝：改为播放成功后暂停；有效明确晚安允许按配置响应。
2. 安静/暂停时段的停止关怀、今晚晚睡指令被提前返回：优先处理有效控制指令。
3. 同分钟多个计划可能被未及时持久化的首个计划阻塞：增加有界的当日执行标记；失败终态允许后续计划继续，删除计划清理标记。
4. 初始活动时间为零可能把刚启动误认为近期活动：使用无活动哨兵，避免无依据就寝询问。
5. 旧/未来情绪及未来文字时间戳可能触发流程：只接受有效时间窗口内的证据。
6. 咳嗽场景从普通切换到低温时可能绕过同类冷却：共用咳嗽冷却。
7. 存储预算满时即使有可删除的旧终态也直接拒绝：先回收旧终态，保留活动记录；仍不足明确返回 STORAGE_FULL。

专项还覆盖：ID 冲突与重复、回调重入取消、队列满、待执行取消、播报失败、错 ID 回复、旧会话回调、过期请求、关闭开关、询问超时、30 天元数据/7 天原文清理、100 项计划上限及活动记录满预算。

## 保留接口及未覆盖项

未来通信层调用 `Care.submit(request, listener)` 即可获得 careId、终态、原因、回复文字、有限意图以及每段原始情绪等元数据；`Care.query` 受保存偏好及清理期限约束。本轮未实现远程传输。

目标 ARM64 真机、真人远场/方言/多人/电视混淆、所有情绪准确率、温度耗电、厂商后台限制、系统改时与整机重启后的可靠闹钟仍未验收。模拟器通过不能替代这些项目。
