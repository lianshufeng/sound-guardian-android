# 高内聚、低耦合审查记录

审查范围：安澜触摸、共情、语音输入/播报、服务会话及两个应用的资源打包。保持现有 sherpa-onnx、YAMNet 和 Canvas 技术栈，采用局部提取及修正，未整文件重写。

## 发现与修正

| 问题 | 影响 | 修正 |
|---|---|---|
| 页面/运行时使用 Worker.Update 和 Sherpa.Result | 更换内部适配器会牵动界面和状态存储 | 改用独立 VoiceUnderstandingResult 和交互层 UnderstandingState |
| 共情标签、连续证据、保持时间混入总状态机 | 表情优先级与情绪识别策略耦合 | 提取纯 Java EmpathyPolicy；BehaviorEngine 保留调度 |
| 输入回调替换没有开启新会话 | 旧片段或已排队回调可能进入新消费者 | 原子失效旧会话，并捕获、校验原回调身份 |
| 倾听状态在锁内同步通知外部代码 | 慢消费者或广播可阻塞 PCM 投递 | 主线程合并状态通知，文字回调仍保序且不合并 |
| 旧推理错误直接暂停当前工作器 | 新窗口可能被旧会话异常关闭 | 异常处理也校验原会话标记 |
| TTS 初始化与释放共享容量 16 的拒绝队列 | 快速启停可能抛拒绝异常，释放任务也可能丢失 | 关闭时撤销待初始化任务，生命周期任务串行保留；待播任务仍按会话替换 |
| 服务清理时可在同一实例启动新采集 | 旧清理逻辑可能关闭新资源 | 新启动等待旧循环完成；回调/延迟任务捕获不可变会话标记 |
| 过期警报在优先级判断后才清除 | 新播报第一帧可能没有同步字幕 | 优先判断前清理过期事件 |
| 页面错过新播报开始，只看到完成 | 旧“正在播报”表情可能残留 | 完成快照可结束较旧请求，仍拒绝过期完成回调 |
| 同种情绪长时间后重新出现，保持计时未刷新 | 下一次情绪可过快切换 | 过期后的新回应重新计算最短保持时间 |
| 原 App 打包未启用的语音模型 | 增加下载、安装和存储开销 | 原 App 排除语音资源，模型源码仍只在 core 维护 |
| Kokoro 未量化模型启动后长期驻留 | 4 GB 级设备容易产生较大的 native heap 和瞬时峰值 | 切换官方 Kokoro v1.1-zh int8；启动预热后释放合成器，动态播报按需加载 |
| Kokoro INT8 在 ARM64 真机生成全 NaN | PCM 转换为全零，字幕及播放进度正常但实际无声 | 单线程无效后改回官方 FP32；保留预热后释放策略，合成结果校验有限值及非静音；正式接口播报已获用户可听确认，低端机峰值重新验收 |
| 低内存设备与普通设备使用相同模型保留时间 | 倾听模型会在短暂使用后继续占用数百 MiB | 根据 `ActivityManager` 内存预算将 SenseVoice/TTS 空闲释放调整为 10 秒或 60 秒 |
| 常驻脸部动画固定 30 FPS | 待机时 RenderThread 持续唤醒，低端机耗电和发热增加 | 低内存设备待机降至约 12 FPS，触摸、眨眼和表情过渡保持 30 FPS |

## 当前边界

- core：模型、输入契约、推理适配器、独立语音结果。
- UnderstandingWorker：PCM 队列、VAD/推理调度、会话失效与资源生命周期，不包含表情映射。
- InteractionPorts / GuardianRuntime：交互数据契约及不可变状态，不依赖工作器实现类型。
- TouchInteraction / EmpathyPolicy：各自处理手势及共情规则，不持有 Android 页面或推理器。
- BehaviorEngine：守护、播报、触摸、共情、待机之间的最终优先级。
- FaceView / MainActivity / ControlPanel：输入及显示，不直接创建推理器或播放器。
- GuardianService：Android 服务、唯一音频采集及能力连接；重启时先完成旧会话清理。
- GuardAudioPipeline / EventHistoryWriter：采集外独立声音推理和写库；8块音频缓冲断流重置证据，300个待写ID合并，写入失败有元数据；不会将积压音频当作实时证据。
- ResourceBudget / HeavyWorkLimiter：TTS与SenseVoice加载、计算共用单项可取消许可，系统内存准入采用待校准估计；不阻塞YAMNet/KWS/VAD。LocalSpeechOutput的缓存和提示音绕过native工作器，普通播放与合成解耦；InputSessionController仍是唯一输入所有者，预热不授予输入权。

以上2026-10-18调度变更的实测与未完成验收以[性能验收](interaction-performance-acceptance.md)为准；下列旧数字不代表本次FP32性能、内存或长期稳定性结论。

## 性能与验证边界

原 App 本次重新生成的 Debug APK 为 22,632,091 字节，约 21.6 MiB；优化前约 636.6 MiB。安澜所需模型继续打包，模型运行内存预算仍需目标真机验证。

增量 APK 删除大条目后可能保留文件中的空洞，因此本次重新生成原 App APK，并同时检查 ZIP 条目和实际文件长度。

回归覆盖：慢状态消费者不阻塞 PCM、新回调不接收旧片段、24 次播音后端快速关闭、跨线程播报会话绑定、页面错过播报开始、警报过期第一帧、共情恢复计时及既有设备闭环。气泡测试显式清理已有界面状态，不依赖设备历史显示偏好。

本轮验证：33 项单元测试、安澜完整设备回归 25 项（资源采样测试默认跳过）通过，原 App 1 项共享核心设备测试通过；生命周期和播报另做 4 项定向复验。两款 Debug 构建及安澜 lint 通过，安澜 392 项、原 App 6 项已启用共享资产的 SHA-256 均与源码一致；原 App 确认不包含三个未启用的语音资源目录。

资源采样测试通过 `ResourceProfileDeviceTest` 按模式单独运行，记录 PSS、native heap、进程 CPU 时间和采样峰值。当前模拟器结果：完整守护约 150～165 MiB PSS；Kokoro int8 加载约 316 MiB、长句合成约 386 MiB、释放后约 96 MiB；SenseVoice 加载约 361 MiB、释放后约 107 MiB；YAMNet/KWS/VAD/SenseVoice 共存约 393 MiB。低内存预算将模型空闲释放缩短到 10 秒，并将待机表情刷新降到约 12 FPS；4 GB 级真实手机仍需验证首次加载时延、温度和长期功耗。

未把本轮结构优化当作情绪准确率或真机长期运行验收。仍需在最终设备验证内存峰值、发热、耗电和不同人声/语气；保持首次集成的验证限制。
